# Локальная сборка и версии

[Документация](README.md) | [English](build.en.md)

## Windows

Основная цепочка работает локально на Windows x64. Нужны **Python 3.10+ с pip** и **Git в PATH**, для первой сборки — доступ в интернет. Visual Studio и отдельная установка Windows SDK не требуются: используется LLVM-MinGW. GitHub Actions для сборки не используются.

```powershell
python tools/local-build.py
```

Команда проверяет последний стабильный LLVM-MinGW и устанавливает его локально в `_tools/llvm-mingw/<выпуск>/toolchain`. Установленный компилятор сохраняется между сборками; при появлении нового стабильного выпуска скачивается новая версия. CMake и Ninja подготавливаются во временном каталоге. SHA-256 загрузок проверяются. Цепочка собирает клиент и утилиты для **x64, x86 и ARM64**, выполняет необходимые проверки и создаёт три ZIP в `dist`. Временные зависимости и промежуточные файлы удаляются даже при ошибке; логи остаются в `dist/local-build-logs`, отчёт — в `dist/local-build.json`, контрольные суммы — в `dist/SHA256SUMS.txt`. Команда ничего не публикует на GitHub.

Установить или проверить локальный компилятор отдельно: `python tools/local_toolchain.py`.

Уже успешно пройденные проверки пропускаются, когда исходники, заголовки, тестовые сценарии и компилятор для соответствующей проверки не изменились. Результаты и зависимости сохраняются в `dist/local-tests.json`; файл следует сохранять между сборками. Существующий отчёт `dist/validation.json` также используется как подтверждение ранее пройденных проверок, если текущие зависимости совпадают с указанным коммитом. Первую сборку без такого подтверждения сопровождает полный набор проверок x64 и x86. ARM64 проверяется по структуре PE и версии ресурсов; запуск на устройстве ARM64 нужен отдельно.

Можно собрать только одну архитектуру или использовать собственные инструменты без загрузок:

```powershell
python tools/local-build.py --arch x64
python tools/local-build.py --offline --toolchain C:\Toolchains\llvm-mingw --cmake C:\Tools\cmake.exe --ninja C:\Tools\ninja.exe
```

Для offline-режима установите `paramiko` в Python заранее, если необходима проверка изменённой SSH-логики. При обычной сборке эта зависимость устанавливается во временное окружение только при необходимости. `--force-tests` явно запускает все проверки заново, например для воспроизведения ошибки. Точные версии инструментов и коммит записываются в `BUILD-INFO.json` внутри ZIP. При ошибке сборки или теста цепочка прекращается и записывает причину в отчёт.

Вариант с установленной Visual Studio 2022 и Windows SDK остаётся доступным через CMake presets:

```powershell
cmake --preset windows-x64
cmake --build --preset windows-x64 --parallel
```

Проверены работающие сборки x64 и x86. ARM64 собрана и проверена по формату PE; пользователь подтвердил работу ранее полученной ARM64-сборки. Новые сценарии 0.85-5 на ARM64 отдельно не проверены. Сборки не подписаны Authenticode.

Номер редакции KiTTY-ng: `python tools/set-release-stage.py 1` для `0.85-1`, `2` для `0.85-2` и далее. База остаётся равной версии PuTTY. Версию повышать только по отдельной команде на выпуск. После изменения каталога переводов выполните `python tools/generate-translations.py`.

## macOS Universal / DMG

Сборка macOS выполняется на **Mac**, отдельно от Windows/Linux. Нужны Python 3.14+ с pip и установленные Apple Command Line Tools (`xcode-select --install`).

```sh
python3 tools/local-build.py --platform macos
# Повторная сборка с уже установленными инструментами:
python3 tools/local-build.py --platform macos --offline
```

Команда проверяет последний стабильный LLVM, сохраняет проверенный компилятор, CMake, Ninja и Pillow в `_tools/macos/native`, использует системный SDK Apple и записывает точные версии и происхождение инструментов. Собирает все шесть файлов ARM64/x86_64, объединяет в Universal 2, подписывает ad-hoc и запускает нативные unit/CLI/AppKit-проверки. Для x86_64 на Apple Silicon нужна Rosetta. Затем создаёт ZIP и HFS+ DMG средствами `ditto`/`hdiutil`, монтирует образ только для чтения и сверяет содержимое, подпись и права запуска.

Результат и отчёты: `dist/macos-native/KiTTY-ng.app`, Universal ZIP/DMG, `macos-build.json`, `macos-dmg.json`, `SHA256SUMS.txt` и `logs`. Прежние архивы в `dist` не заменяются. Временные каталоги очищаются; установленный компилятор сохраняется. `--skip-dmg` допустим для диагностики. `--compiler /usr/bin/clang --offline` задаёт Apple Clang для диагностической сборки; обычная сборка использует последний стабильный LLVM.

Сетевые проверки с синтетическими данными выполняет `test/macos_native_runtime.py`; Paramiko нужен только для тестового loopback-сервера. Команды и границы покрытия приведены в [отчёте нативной проверки](macos-native-validation.md). Подпись ad-hoc не заменяет Developer ID и нотариальное заверение Apple.

## Правила выпусков

`0.85` — версия импортированной базы PuTTY, число после дефиса — редакция KiTTY-ng: `0.85-1`, `0.85-2`, `0.85-3`, `0.85-5`. Теги: `v0.85-5`. Версии клиента и всех утилит совпадают. Версия добавляется в имена ZIP/DMG, архитектура — в имена Windows EXE; номер версии в имени EXE не используется.

Номер повышается только по отдельной команде на выпуск. Обновление документации не создаёт новый релиз. Старые опубликованные релизы сохраняются.

## Сборка полного релизного комплекта

```powershell
# Windows: пакеты Windows/Linux
python tools/release-build.py --build-only
```

```sh
# Mac: пакет macOS; затем сборка комплекта с соответствующими артефактами Windows/Linux:
python3 tools/release-build.py --build-only
python3 tools/release-build.py --assemble-only
```

Windows и Linux собираются отдельно; macOS — на Mac. Для сборки комплекта нужны пакеты всех платформ из одного чистого Git checkout/коммита, совпадающие версии и нативные отчёты macOS/Linux. Команда сверяет их происхождение и контрольные суммы. Публикация в прежний репозиторий GitHub выполняется только по отдельной команде на выпуск; предыдущие релизы и вложения сохраняются.

По прямой команде обновить только Mac-пакет существующего выпуска: зафиксировать и отправить исходники в GitHub, собрать на Mac, выполнить недостающие проверки, затем `python3 tools/update-macos-release.py --publish`. Сценарий проверяет чистый коммит и отчёты, сохраняет прежний DMG под архивным именем, загружает новый основной DMG и обновляет русские заметки. Тег, Windows/Linux-вложения и предыдущие релизы сохраняются. Без `--publish` только сохраняется снимок состояния GitHub для проверки и повторного запуска. Полный новый выпуск выполняется обычной процедурой с новым номером.
