# KiTTY-NG для macOS Universal

**macOS Portable + общие Windows-профили.** Приложение не требует установки: `KiTTY-NG.app` можно держать рядом с Windows EXE и использовать тот же каталог `Sessions`, ключи сервера и относительные ссылки на SSH-ключи. Настройки сохраняются снаружи `.app`; профили исходного портативного KiTTY также читаются.

Выпуск 0.85-3 поставляется в DMG с нативным приложением и пятью Universal-утилитами: Apple Silicon ARM64 и Intel x86_64. Требуется macOS 13 или новее. Основная работа подтверждена пользователем на MacBook Air M3; специальные сценарии проверяются отдельно.

[English](macos.en.md)

## Установка из DMG

Откройте `kitty-ng-0.85-3-macos-universal.dmg` и скопируйте `KiTTY-NG.app` в свою папку. Для общего portable-каталога поместите `.app` рядом с Windows EXE и `Sessions`. Извлеките образ перед запуском: сохранять данные в read-only DMG нельзя. Дополнительные инструкции и диагностические command-файлы находятся в папке `Instructions`; для их запуска перенесите command-файлы рядом с `.app`.

## Сборка локально на Windows

```powershell
python tools/local-build.py --platform macos
```

Команда проверяет стабильные LLVM и macOS SDK в официальных источниках, устанавливает инструменты в `_tools/macos`, собирает ARM64 и x86_64 и объединяет каждый исполняемый файл. Установленные инструменты сохраняются, промежуточные файлы удаляются. Для повторной сборки без сети доступен `--offline`. GitHub Actions и доступ к Mac для компиляции не требуются.

Архив: `dist/kitty-ng-0.85-3-macos-universal.dmg`. Сведения об инструментах, зависимостях и контрольная сумма: `dist/macos-build.json`. Сборка рассчитана на macOS 13 и новее; совместимость с нижней границей ещё требует проверки.

Внутри `KiTTY-NG.app` находятся нативный AppKit-клиент с терминалом и SSH-ядром PuTTY и пять консольных помощников: `klink`, `kscp`, `ksftp`, `kittygen`, `kageant`. Каждый файл содержит обе архитектуры. Помощники находятся в `Contents/Helpers`; нативный GUI KiTTYgen и меню Kageant используют эти встроенные помощники.

## Общие настройки с Windows

Скопируйте приложение из DMG на Mac **рядом с** Windows EXE, `kitty.ini`, `Sessions`, `SshHostKeys`, `Proxies` и каталогом ключей. Данные хранятся снаружи `.app`. Клиент открывает существующие профили, показывает папки в `<>`, поддерживает переход `..` и поиск без учёта регистра. При переносе приложения системой в AppTranslocation нужно вручную выбрать общий каталог.

Корень можно явно задать переменной `KITTY_NG_PORTABLE_DIR`; консольные помощники также принимают `--portable-dir`. Сохранённые относительные пути к PPK и сертификатам разрешаются от этого корня, а не от текущего каталога. Подключён формат пароля оригинального KiTTY. Настройки каталогов и суффиксов из `putty.conf` и `kitty.ini` учитываются. Эти INI-файлы читаются в UTF-8, UTF-16 с BOM и старой CP1251; относительные каталоги разрешаются от общего портативного корня. Абсолютные пути Windows и переменные вида `%USERPROFILE%` на Mac не преобразуются автоматически.

Mac-адаптер записи сохраняет неизвестные строки профиля и использует отдельные поля шрифтов `Mac...Name`. Кнопки «Новый» и «Изменить» открывают редактор профилей. Сохранение сохраняет неизвестные поля, отказывается перезаписывать изменённый извне профиль и преобразует внутренние файловые ссылки в относительные. Изменение имени создаёт копию профиля, исходный сохраняется. При подтверждении ключа сервера и сохранении seed-файла запись в общий каталог возможна. Для первого теста рекомендуется копия общего каталога.

## Подпись и первый запуск

Пакет подписывается локальной ad-hoc подписью без Developer ID и нотариального заверения Apple. На Windows проверяются обе архитектуры всех шести файлов, хеши подписанного кода, Info.plist и ресурсов; отдельные проверки повреждают копии кода и ресурса и проверяют отказ валидатора. Это проверка структуры и целостности, а не проверка Gatekeeper или успешного запуска.

При блокировке macOS используйте «Настройки системы → Конфиденциальность и безопасность → Всё равно открыть». При необходимости приложение можно заново подписать на Mac:

```sh
codesign --force --deep --sign - KiTTY-NG.app
codesign --verify --deep --strict --verbose=2 KiTTY-NG.app
```

## Что проверить на Mac

1. Запустить приложение из общей папки, открыть вложенный сеанс, проверить русский язык и быстрый поиск.
2. Подключиться по SSH: сохранённый пароль, затем отдельный профиль с относительным PPK; для зашифрованного PPK проверить запрос парольной фразы.
3. Проверить подтверждение и повторное чтение ключа сервера, профиль прокси, нестандартный каталог и расширение сеансов.
4. Проверить UTF-8, русскую раскладку, Ctrl+C, стрелки, F-клавиши, Cmd+C/Cmd+V, выделение мышью, прокрутку, изменение размера и закрытие окна.
5. Переместить общую папку и повторить открытие сеанса с ключом. Убедиться, что Windows-профили не переписаны.
6. На Apple Silicon отдельно проверить Intel-часть через Rosetta: `arch -x86_64 KiTTY-NG.app/Contents/MacOS/kitty-ng` (если Rosetta установлена).

## Добавленные возможности для проверки

- Редактор: соединение, пароль, ключ/сертификат, агент, терминал, прокси, автоматизация, передача файлов, окно и заметки. «Все настройки» показывает дерево всех сохраняемых параметров ядра PuTTY; логические значения имеют флажки, перечисления — списки, сложные списки туннелей/окружения/алгоритмов используют штатный формат хранения. Дерево формируется штатным сериализатором, поэтому включает настройки со специальным кодированием, а не только скалярные поля. Раскладка отличается от оригинальных форм PuTTY.
- Сохранение выбора English/Русский в общем `values.ini`, кнопка «Применить», переключение открытых редакторов и KiTTYgen без потери введённых данных. Kageant имеет меню «Язык» в строке меню macOS. По умолчанию используется язык macOS.
- Отправка/скачивание через встроенный `kscp`, включая перетаскивание файлов и каталогов. Помощник получает снимок текущего Conf через анонимный stdin-канал: сохранённый пароль, PPK, отдельный сертификат, агент и прокси. Пароли не добавляются в командную строку или временный профиль. Проверяется собственный подписанный Universal-помощник внутри `.app`, PATH не используется.
- Автокоманды и UTF-8 скрипты отправляются удалённому терминалу после готовности SSH-канала, с задержками начала, символов и команд. Локально скрипты не исполняются. Для Scriptfile поддерживаются BOM и CR/LF; предел 1 MiB.
- Переподключение при ошибке связи и после пробуждения Mac; отмена проверки ключа/аутентификации не запускает повторное соединение. Нормальный выход закрывает окно по параметру CloseOnExit.
- Контекстное меню: настройки, журнал, передача файлов, скрипт, перезапуск, поверх окон, защита ввода, скрытие и полный экран. KiTTY-комбинации из `[Shortcuts]`, в том числе фигурные скобки, `Ctrl+F3`, старые числовые коды и пользовательская отправка текста; по умолчанию Ctrl+F2/F3/F4/F6/F7/F9 и Shift+F12; Cmd+C/V и Cmd+L. Защиту ввода можно выключить той же комбинацией.
- Ctrl+щелчок открывает HTTP/HTTPS; мышь и колёсико передаются в приложения терминала, включая правую/среднюю кнопку. Shift+правый щелчок открывает местное меню.
- Размер/положение окна используют отдельные Mac-поля; Windows-геометрия не переписывается. Прозрачность, запуск скрытым, развёрнутым/полноэкранным, сохранение при выходе, разрешение OSC 52 задаются в редакторе.
- KiTTYgen: Ed25519/RSA/ECDSA, загрузка, генерация, публичный ключ, PPK/OpenSSH/RFC4716, смена парольной фразы через нативный запрос. Kageant: запуск, добавление, список, удаление всех ключей и остановка. Сокет агента приватный и временный; данные сессий остаются в общей папке. В строке меню можно вернуть скрытые терминалы.
- «Обновить профили» преобразует существующие Mac-пути к ключам, сертификатам, Scriptfile/IconeFile и распознанным файлам Autocommand внутри корня. Windows-пути не угадываются; сначала преобразуйте их Windows-клиентом на Windows.

## Границы текущего переноса

Основной SSH-терминал после исправлений проверен пользователем на M3. Все добавленные выше GUI-функции собраны, но их совместная работа на Mac пока не подтверждена. В частности, необходимо проверить передачу с зашифрованным ключом/агентом, сохранение общего профиля и длительную работу.

Перечисленные ранее шесть блоков реализованы в исходниках этой итерации: пользовательские сочетания, SSH CA/GSSAPI, дерево сохраняемых настроек, дополнительные шрифты/двойная высота, имена CP1251 и дополнительные переводы консольных сообщений. Это готовность реализации к нативной проверке, а не подтверждённая работа всех сценариев на Mac.

SSH CA доступны через меню приложения «Центры сертификации SSH…»: создание/открытие, публичный ключ OpenSSH/base64, выражение выбора серверов, разрешения RSA/SHA-1/256/512, сохранение и удаление. Ключ и выражение проверяются ядром PuTTY. Хранилище — отдельный `SshHostCAs` в общем портативном корне, формат записей KiTTY; читаются также записи `key=value` PuTTY Unix. Windows-клиент пока использует своё реестровое хранилище CA: автоматической синхронизации CA с ним нет. Обычные профили и ключи серверов остаются общими.

GSSAPI собирается в режиме DYNAMIC и на Mac обращается к системному `/System/Library/Frameworks/GSS.framework/GSS`, без дополнительного комплекта Kerberos. Параметры GSSAPI доступны в дереве настроек. Аутентификация требует действующих Kerberos credentials и подходящего сервера; она ещё не проверена на настоящем Mac.

Чтение имён сначала использует UTF-8, затем CP1251; при поиске старого percent-encoded файла/каталога сохраняется его физическое имя. Проверка на Windows подтверждает преобразование байтов, а запись/повторное открытие настоящих файлов на Mac проверяется новым нативным smoke-сценарием.

Обычный, жирный, широкий и широкий жирный шрифты хранятся в отдельных Mac-полях. Пустой дополнительный шрифт означает автоматический выбор. Для двойной ширины/высоты применяются геометрическое масштабирование и совпадающие top/bottom срезы; отдельно проверены расчёты, визуальный результат требует Mac.

Программные сообщения используют общую таблицу перевода и дополнительные Unix-форматы; форматные аргументы проверены. Названия ключей конфигурации, алгоритмов, команды/переменные оболочки, сообщения сервера и операционной системы сохраняются как данные. Автоматическое определение удалённого каталога использует OSC 7, если оболочка его сообщает; иначе показывается сохранённый каталог и явное подтверждение. Команда `pwd` поверх MC не вводится.

Исключённые Windows-матрицей устаревшие расширения (ZModem, RuTTY, опасные локальные хуки, старые комплекты Cygwin и т. п.) не возвращаются в Mac-порт. Сохранение их неизвестных полей не означает поддержки функции. Статус Windows-миграции не изменён; состояние Mac-порта описано отдельно в `docs/macos-migration.json`.

## Проверки этой итерации

`test/macos_automation.py` компилирует настоящий production-парсер автокоманд и проверяет UTF-8, BOM, CR/LF, escape-последовательности, композицию скрипта и автокоманд, NUL/повреждённый Unicode, ограничения размера и недоступный Windows-путь. `test/macos_portable.py` использует извлечённые production-функции чтения исходного формата KiTTY и разрешения путей; проверяет дубликаты, пустые/русские значения, непрерывность неизвестных байтов, повреждения, целые числа и ссылки от корня. Буферные/платформенные зависимости подменены адаптерами для Windows; это не тест нативной атомарной записи или AppKit.

Успешные проверки прежних исправлений MC и рекурсии Ldisc не запускались повторно: их логика не менялась. При каждой новой сборке проверяются две архитектуры всех EXE, подписи, ресурсы и отказ при изменении кода/ресурсов. Результаты лежат в `dist/*-test.json` и `dist/macos-build.json`.

В архив включён `Smoke-test KiTTY-NG.command`: проверка штатным codesign, архитектуры и версии пяти помощников, создание и преобразование синтетического Ed25519, приватные права файла, отклонение повреждённого снимка Conf и ограниченный по времени агент. Дополнительно скрытый режим `--self-test-portable`, разрешённый только в выделенном временном корне и с `KITTY_NG_SELF_TEST=1`, проверяет реальные сериализаторы цветов/туннелей, относительный ключ, открытие/сохранение CP1251 имени и создание/чтение/удаление SSH CA с синтетическим публичным ключом. Временный каталог `/tmp/kitty-ng-smoke.*` удаляется через trap. Журнал `kitty-ng-smoke-test.log` сохраняется рядом с приложением; личные профили не используются. Запускать через Terminal (`zsh` и полный путь) либо двойным щелчком, если macOS разрешает. Этот скрипт ещё не выполнен на Mac.

## Исправление первого падения на M3

Отчёт от 11 октября 2026 года показал цепочку `mainchan_ready → ldisc_echoedit_update → echo_edit → ldisc_echoedit_update` и переполнение стека. Mac Seat теперь использует `nullseat_echoedit_update`, как GTK-интерфейс PuTTY: уведомление не вызывает повторное обновление Ldisc. Общий код Ldisc и Windows-обработчики не изменены.

Проверка `test/macos_echoedit.py` компилирует исходный C-код обновления Ldisc, его состояние и выбранный Mac callback для запуска на Windows. Она выполняет 360000 обновлений с принудительными и автоматическими режимами эха/редактирования, проверяя завершение вызовов и запрос отправки строки при выключении редактирования. Результат сохранён в `dist/macos-echoedit-test.json`; это проверка причины рекурсии, а не замена запуска AppKit на Mac.

## Оформление терминала

Терминал помещён в отдельную нативную рамку с внутренними полями 12 pt и тонким закруглённым контуром. Начальный размер и запрос размера от сервера учитывают поля: количество строк и столбцов не уменьшается. Отступы находятся снаружи терминального NSView, поэтому рисование, курсор, выбор текста, координаты мыши и положение IME используют прежнюю систему координат. Фон области терминала берётся из палитры сеанса. Вид рамки и изменение размера требуют визуальной проверки на Mac.

## MC и второе падение

Исправлено определение ширины символов: используется независимая от локали Unicode-таблица PuTTY вместо libc `wcwidth`. Размер фонового прямоугольника берётся из числа ячеек в run и атрибутов wide/combining. Каждая обычная буква рисуется в своей ячейке; естественное продвижение строки и лигатуры не смещают колонки. Проверка `test/macos_grid.py` воспроизводит строку MC с кириллицей и рамками при `LC_ALL=C`, а также wide/combining; результат сохранён в `dist/macos-grid-test.json`. Рисование на настоящем Mac требует подтверждения пользователя.

Отчёт второго падения показывает `objc_release → AutoreleasePoolPage::releaseUntil`, но не называет освобождённый объект. Пользователь уточнил, что окна не закрывались. Поэтому окончательная причина пока не установлена. У всех самостоятельно созданных NSWindow выключен автоматический release при закрытии, а делегат приложения имеет точное время жизни; это исправления владения объектами, а не доказательство устранения второго падения. Статический анализ Clang до этих изменений не сообщил об ошибках.

Для диагностики закройте обычный экземпляр, распакуйте `.app` и `Diagnose KiTTY-NG.command` из одного архива в общий каталог и запустите command-файл. Повторите действия до сбоя и передайте `kitty-ng-diagnostic.log`. Диагностический режим включает `NSZombieEnabled` и не предназначен для постоянной работы. Xcode для этого не требуется. Если macOS не разрешает двойной щелчок, командный файл можно запустить из Terminal через `zsh` с его полным путём.

Источники Apple: [владение NSWindow при ARC](https://developer.apple.com/documentation/appkit/nswindow/isreleasedwhenclosed), [диагностика освобождённых объектов](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/ManagingMemory/Articles/FindingLeaks.html).

## Исправления передачи файлов и порядка сеансов

Каталоги отображаются перед сеансами, внутри каждой группы применяется естественная алфавитная сортировка; `..` остаётся первым. Устранён лишний сдвиг индекса в общем обработчике kscp после `--`: первый локальный путь больше не пропускается. Регрессионная проверка `test/pscp_arguments.py` воспроизвела ошибку на прежнем обработчике и проверила исправленные upload/download/list/multiple-file аргументы без подключения к серверу. При отправке каталогов GUI автоматически добавляет `-r`, пути передаются отдельными аргументами без shell-склейки. Реальная передача после этого исправления требует повторной проверки на Mac.

## Завершение оставшихся блоков

Добавлены host-проверки `test/macos_shortcuts_names.py` (7872 комбинации, синтаксис, Unicode/CP1251), `test/macos_font_geometry.py` (геометрия top/bottom) и чтение CA-форматов в `test/macos_portable.py`. `test/macos_ini_text.py` проверяет Unicode/BOM, UTF-16 surrogate pairs и отклонение повреждённого текста INI. В дополненных переводах проверяются сигнатуры printf-аргументов. Общие расчёты имён и сочетаний не зависят от AppKit; их можно использовать в будущем GTK-порте Linux.

Windows-задачи, сообщённые во время этой итерации, записаны отдельно в [planned.md](planned.md). Они пока не реализованы: кодировка/оформление журнала, запуск x64 KiTTYgen/Kageant, заголовок Receive file вложенное меню сеансов и обработка Shift в Midnight Commander.

## Последующие локальные доработки

Mac записывает seed в `kitty-ng-macos.rnd`, Windows по умолчанию в `kitty-ng-win.rnd`. Отдельный Mac-путь можно указать ключом `macseedfile` в `putty.conf`: Windows-ключ `seedfile` больше не выбирает Mac-файл. Это исключает совместную запись двух платформ в один seed; конфликты между одновременно работающими Mac остаются отдельным сценарием. Старые пользовательские файлы не удаляются.

У профилей добавлено «Дублировать»: новое имя, редактор с настройками исходного профиля, запись по «Сохранить». Исходный профиль проверяется на изменения и не перезаписывается, неизвестные поля переносятся вместе с исходным файлом. Ранее добавленные «Новый», «Изменить», «Удалить» остаются доступны. Нативная проверка нового действия ещё нужна.

По последующей команде пользователя исправлены Shift + стрелки (включая старые профили), точные локальные запросы парольной фразы ключа и upload без запроса каталога. Upload использует переданный текущий каталог, затем сохранённый PSCPRemoteDir, затем «.» — начальный каталог нового удалённого SSH/SFTP-подключения; обычно это домашний каталог. Download запрашивает имя удалённого файла. Произвольные серверные запросы остаются данными сервера.

Для MC добавлено рисование линий псевдографики по границам ячеек: высота шрифтового глифа больше не создаёт разрывы вертикальных рамок. Проверены 768 вариантов геометрии, но внешний вид Retina/AppKit требует проверки на настоящем Mac. `test/macos_followups.py` также проверяет выбор каталога upload и RU/EN запросы ключа.

## Исправление смены языка и начального порта

Стандартные элементы AppKit больше не локализуются рекурсивно: для NSSearchField меняется только placeholder, а его внутренние кнопки сохраняются. Названия English/Русский в выборе языка неизменны. Defaults SSH/22 задаются до создания браузера, поэтому «Новый» работает до первого подключения. Сохранённые существующие порты не переписываются. Smoke-test включает native-only AppKit проверку шести переключений, сохранности поиска и начального SSH/22; кросс-сборка эту проверку не выполняет.

```text
KiTTY-NG/
├── KiTTY-NG.app
├── kitty-ng-x64.exe
├── kscp-x64.exe
├── kitty-ng.portable
├── kitty.ini
├── Sessions/
├── SshHostKeys/
└── SSH-Keys/
```

Общий механизм исправляет и KiTTYgen: при смене языка сохраняются названия языков, выбранный алгоритм, размер ключа, комментарий, путь и публичные данные. Для нового SSH-профиля унаследованное нулевое значение порта заменяется 22; существующие профили не переписываются.
