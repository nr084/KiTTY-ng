# Перенос расширений KiTTY: итог

Миграция Windows-клиента на PuTTY 0.85 закрыта в текущих исходниках. Отдельный нативный Mac-порт находится в разработке; его состояние описано в [macos.md](macos.md). Каждое найденное расширение получило решение: перенести, заменить стандартной возможностью или исключить. Непринятых решений и списка «перенести позднее» нет. Это завершение выбранного объёма миграции, а не обещание полного совпадения со старым KiTTY.

Последний этап переноса входит в выпуск **0.85-2**. Ниже описаны его возможности и ограничения совместимости.

## Основание аудита

История KiTTY сохранена до `75fa2abcd220c17249ff7252f8d5224137001f2d` в ветке `upstream-kitty`. Замена рабочего дерева официальным PuTTY 0.85 зафиксирована в `d5c8fc06d387c58e5434818fbf8b6c3ed4e9fb23`. Старые патчи адаптированы к современным интерфейсам, вместо механического копирования PuTTY 0.76.

[Аудит](kitty-feature-audit.json) охватывает 351 исходный файл, все 27 переключателей `MOD_*` и дополнительные поля старого `Conf`. [Матрица решений](kitty-migration-decisions.json) содержит назначения каждого переключателя и поля, причины исключений и функции без отдельных переключателей. `python tools/audit-kitty.py` повторно извлекает инвентарь из сохранённого коммита и отклоняет пропуски, неизвестные элементы и повторные назначения. Старое дублирующее дерево `0.76_My_PuTTY` исключено.

## Перенесено

| Возможность | Реализация |
| --- | --- |
| Портативные настройки | Старые `Sessions`, `SshHostKeys`, `Proxies`, `%XX`, `Ключ\значение\`, вложенные папки, расширения файлов, `putty.conf`, `kitty.ini`; неизвестные поля сохраняются |
| Сеансы | Главная папка, `<каталоги>`, `..`, поиск без учёта регистра, Unicode-имена, список сеансов Kageant из текущего хранилища |
| Сохранённый пароль | Старый обратимый алгоритм и `cryptsalt`, root, SSH password и keyboard-interactive; это совместимость формата, а не защищённое хранилище |
| Передача файлов | Kscp своей архитектуры, перетаскивание, отправка/получение, SCP/SFTP, сохранённый ключ/пароль, Unicode, текущий удалённый каталог и параметры |
| Автоматизация | `Autocommand`, `ScriptfileContent`, UTF-8 `Scriptfile`, задержки после входа/между строками/символами, ручная отправка команды и скрипта |
| Горячие клавиши | Настраиваемые действия и текст из `[Shortcuts]`, старые числовые коды и `{CONTROL}{F3}`, новые `Ctrl+F3`; DisableAltGr |
| Окно | Прозрачность, трей, maximized/fullscreen, поверх окон, защита ввода, восстановление положения, сохранение сеанса при выходе, ICO, заметки, вывод окна при звонке, шаг прокрутки |
| Переподключение | Потеря установленного SSH-соединения и пробуждение Windows; обычный выход и отказ входа не запускают повторный вход |
| Прокси | Выбор существующего общего профиля `Proxies`, параметры SOCKS/HTTP/Telnet/local command; отсутствующий или повреждённый выбранный профиль блокирует соединение |
| Ссылки | Ctrl+щелчок по HTTP/HTTPS открывает браузер Windows |
| Буфер обмена | OSC 52: только явно разрешённая запись UTF-8, проверка Base64 и ограничение размера; удалённого чтения нет |
| Интерфейс и утилиты | Русский/английский, язык Windows по умолчанию, применение языка клиента, отдельные меню KiTTYgen и Kageant, современные утилиты PuTTY своей архитектуры |

Клиент и помощники запускают только EXE своей архитектуры из собственного каталога с проверкой PE. Сборки x64, x86 и ARM64 создаются локально. Нативная проверка ARM64 на ARM-машине остаётся отдельной аппаратной проверкой; это не незавершённый перенос исходников.

## Где находятся новые настройки

- **Соединение → Автоматизация**: команды и скрипт после входа. Для `Autocommand` используются `\n`, `\r`, `\t`, `\\`; в файле скрипта обратные косые черты остаются буквальными. Скрипт — UTF-8, допускается BOM, максимум 1 МиБ. Данные отправляются в удалённый терминал после аутентификации, локально не исполняются.
- **Соединение → Профили прокси**: существующие общие профили. Редактор отдельных прокси не добавлен; обычные настройки прокси сеанса остаются на штатной странице PuTTY.
- **Окно → Расширения**: поведение окна, горячие клавиши, ссылки, OSC 52 и ICO. **Сеанс → Заметки**: комментарий к сеансу.
- Меню терминала: поверх окон, защита ввода, отправка команды/скрипта, запуск Kageant/KiTTYgen. При включённых горячих клавишах по умолчанию: Ctrl+F2 — скрипт, Ctrl+F3/F4 — отправка/получение файла, Ctrl+F6 — трей, Ctrl+F7 — поверх окон, Ctrl+F9 — защита ввода, Shift+F12 — автокоманда.

Пример `kitty.ini` для отправки удалённой команды:

```ini
[KiTTY]
shortcuts=yes

[Shortcuts]
list={SHIFT}{F10}
{SHIFT}{F10}=echo ready\n
```

Старые `initdelay`, `commanddelay`, `bcdelay` в `kitty.ini` задаются в секундах; новые поля профиля и интерфейс — в миллисекундах. `FailureReconnect`, `WakeupReconnect` и глобальный `ReconnectDelay` импортируются в текущую настройку.

`Scriptfile` и `IconeFile` внутри портативного корня сохраняются относительными ссылками, как ключи и сертификаты. Массовое обновление профилей преобразует также старые файловые ссылки `Autocommand` с расширениями `.sh`, `.ksh`, `.sql`, `.txt`, `.ps1`. Обычные команды не преобразуются. Внешние файлы остаются абсолютными. Неизвестные строки, пароль и форматирование массовый обработчик сохраняет побайтно.

## Замены и исключения

| Старое расширение | Итог и ограничение |
| --- | --- |
| Встроенные Pageant/PuTTYgen, launcher | Отдельные Kageant/KiTTYgen, папки сеансов и задачи Windows; старые копии утилит не дублируются |
| FAR2L, собственные таблицы клавиш | Стандартный TTY-режим современного PuTTY, xterm 216+ и xterm-style bitmap; [FAR2L документирует поддержку PuTTY](https://github.com/elfmz/far2l/blob/master/far2l/bootstrap/scripts/FarRus.hlf.m4). Старый FARTTY-протокол, key-up и удалённое чтение clipboard не перенесены. OSC 52 дополняет только запись |
| PuTTYX/TuTTYColor | Стандартные цвета PuTTY, true colour и палитра; дополнительные старые варианты палитры не импортируются автоматически |
| RuTTY expect | Условный движок исключён. Обычные стартовые скрипты поддерживаются; сценарии ожидания/условий RuTTY не исполняются |
| Фоновые JPEG, слайд-шоу, старый набор значков | Исключены из области терминального клиента. Остаются цвета, прозрачность и пользовательский ICO |
| Zmodem | Старый внешний winpzmodem исключён; SSH-файлы передаются SCP/SFTP. Для последовательного порта равноценной замены передачи файлов нет |
| Port knocking | Старые блокирующие IPv4-последовательности исключены. Если сервер требует knocking/SPA, перед SSH нужен отдельный клиент |
| Скрытый чат, встроенный редактор, дампы, local-command OSC | Исключены. Удалённый терминальный вывод не запускает локальные команды |
| ADB, Cygterm/CtHelper, старые Cygwin DLL, UPX-дубликаты, IE/SSH-browser | Не входят в поставку; используются штатные протоколы PuTTY и актуальные отдельные приложения |
| WinSCP-специфичные аргументы | Не импортируются в Kscp. WinSCP настраивается отдельно; штатная передача реализована через Kscp |
| Roll-up, межоконный Ctrl+Tab, kiosk-кнопки | Исключены; остаются управление окнами Windows, трей и защита ввода |
| Произвольные browser/regex-команды, локальные макросы Shortcuts | Исключены. Поддерживаются HTTP/HTTPS и текстовые команды; неизвестные escape-последовательности сохраняются как текст |
| HostAlt, AntiIdle, AutocommandOut | Исключены: сервер выбирается явно, keepalive поддерживает соединение без имитации пользовательских клавиш, завершение настраивается на сервере |
| LogTimestamp, LogTimeRotation | Старые построчные метки и периодическая ротация не перенесены. Штатные журналы PuTTY, датированные имена и метки пакетного журнала остаются; внешняя ротация настраивается отдельно |
| Печать clipboard, tunnel-title, NoFocusReporting | Специальные старые механизмы исключены; обычная терминальная печать и журнал событий остаются |
| Мастер-пароль всего файла | Не поддерживается. Нераспознанные непустые профили не перезаписываются; зашифрованные профили сначала экспортируются старым KiTTY в обычный формат. Сохранённый пароль сеанса поддерживается |

Сохранение неизвестного поля не означает исполнение исключённой функции. Автоматического импорта старого реестра KiTTY нет: основной сценарий совместимости — портативные каталоги. Исторические идентификаторы формата хранения не переименованы.

## Проверки

Локальная цепочка `python tools/local-build.py` проверяет сборку и PE всех архитектур, а на x64/x86 — изменённые настройки, парсеры, Unicode, старые профили, защиту от перезаписи непрочитанных файлов, SSH-аутентификацию, командную очередь, скрипт после переноса каталога, горячие клавиши, защиту ввода, OSC 52, сохранение положения и настоящий SOCKS5-прокси. Отдельно проверяется отсутствие прямого подключения при ошибке выбранного прокси. Используются только искусственные профили и локальные серверы; реальный clipboard не читается и не изменяется.

Успешные проверки неизменённых участков повторно используются с сохранёнными входными данными и обоснованием. Точные инструменты и результаты находятся в локальных `dist/local-build.json`, `dist/local-tests.json` и `dist/local-build-logs`; временные каталоги сборки удаляются.
