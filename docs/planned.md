# Запланированные задачи

## Следующая версия Windows — журнал событий

Записано по просьбе пользователя 12 октября 2026 года. Windows-пункты реализованы локально в последующей Windows-итерации, без релиза; номер версии повышать только по отдельной команде на релиз. Итоги: [windows-fixes.md](windows-fixes.md).

- Исправить повреждённую кодировку русских сообщений в окне «Журнал событий KiTTY-NG». На предоставленном скриншоте русские сообщения отображаются как «Р…», английские строки читаются нормально. Проверить границу UTF-8/UTF-16 при добавлении строк, открытии окна и копировании журнала; точная причина ещё не установлена.
- Переработать оформление того же окна: ровные отступы и размеры элементов, удобное изменение размера, аккуратная нижняя панель; группу кнопок «Копировать» и «Закрыть» расположить по центру. Сохранить прокрутку и выделение событий.
- При проверке использовать синтетические сообщения на русском и английском, включая время, Unicode и копирование текста. Не публиковать содержимое пользовательского журнала в репозитории.

## Следующая версия Windows — запуск утилит x64

- Из меню `kitty-ng-x64.exe` не запускается KiTTYgen: показано «Не удалось запустить утилиту соответствующей архитектуры». Проверить поиск `kittygen-x64.exe` рядом с клиентом, распознавание PE x64, путь/аргументы запуска, зависимости и ошибку Windows при создании процесса. Причина пока не установлена.
- Аналогично не запускается Kageant; проверить `kageant-x64.exe` тем же способом. Сопоставить обе ошибки, чтобы проверить общий механизм вызова утилит.
- Сохранить выбор утилиты своей архитектуры из каталога клиента; не обходить ошибку запуском версии другой архитектуры или поиском через PATH. Проверить русские имена каталогов и пробелы в пути.

## Следующая версия Windows — вложенное меню сохранённых сеансов

- Заменить плоский длинный список путей сеансов иерархическими подменю по существующим папкам. Например, `Работа/Сервер` показывать как «Работа → Сервер».
- Поддержать несколько уровней вложенности; в каждом меню сначала каталоги, затем сеансы, внутри групп — сортировка по имени. Сеансы корневого каталога оставить в корне меню.
- В подменю показывать только имя текущего уровня. Полный идентификатор сеанса сохранить для открытия, не переименовывать файлы и не менять формат хранения.
- Проверить Unicode, одноимённые сеансы в разных папках и выбор правильного профиля после обновления списка.

## Следующая версия Windows — Shift в Midnight Commander

- Пользователь сообщает: в оригинальном KiTTY удержание Shift позволяло выделять файлы в Midnight Commander; в KiTTY-NG такое поведение не работает.
- Сравнить обработку модификатора в оригинальном KiTTY, актуальном PuTTY и KiTTY-NG. При воспроизведении установить конкретное действие: Shift+стрелки, Shift+щелчок или Shift+перетаскивание; не предполагать его по описанию.
- Проверить режимы Shift+стрелок, приоритет локальной прокрутки/выделения терминала, mouse reporting/override, отправляемые последовательности и TERM/terminfo. Отличать выделение текста терминала от отметки файлов внутри MC.
- Проверить результат на одинаковом сервере, версии MC и настройках сеанса; после исправления сохранить обычное выделение текста и поведение Shift вне MC. Причина установлена: режим SHARROW_APPLICATION не передаёт Shift; новый default Windows — SHARROW_BITMAP. Исправлен также приоритет модификаторов в application cursor mode.

## macOS — Shift + стрелки в Midnight Commander

- По проверке пользователя Shift + стрелки также не отмечают файлы в MC на Mac. Сопоставить настройку ShiftedArrowKeys, события AppKit и отправляемые CSI/SS3 последовательности; проверить обычный и application cursor mode. Исправлены общий форматтер (включая сохранённый старый режим) и default macOS. Нативную передачу AppKit и выделение в MC нужно проверить в новом архиве.

## macOS — каталог назначения при перетаскивании

- По просьбе пользователя убрать обязательный вопрос о каталоге назначения при drop-загрузке и согласовать с Windows. Пользователь предполагает домашний каталог: сначала установить фактическое поведение Windows (текущий удалённый каталог или home fallback), затем реализовать одинаковое поведение. Реализовано по последующей команде пользователя: upload без вопроса использует известный текущий путь, настроенный pscpremotedir или «.»; download по-прежнему запрашивает удалённый файл.

## macOS — действия над профилями

- Добавить у списка профилей «Новый», «Изменить», «Удалить», «Дублировать». Дублирование запрашивает новое имя и открывает настройки копии, сохраняется только по подтверждению; исходный профиль не изменяется. Реализовано в исходниках после Windows-проверки; новый Mac-архив собирается без релиза.

## Windows — меню значка в трее

- Возвращено по правому щелчку «Восстановить / О программе / Выход»; двойной щелчок восстанавливает окно. Выход использует обычное закрытие с защитой от потери сеанса. Поддержаны English/Русский.

## Следующий выпуск — порт нового SSH-сеанса

- По просьбе пользователя 12 октября 2026 года: в macOS и Windows для новых SSH-профилей показывать и сохранять порт 22, а не 0. Mac-часть реализована по последующей прямой команде: defaults SSH/22 задаются до запуска браузера. Windows-часть остаётся на следующий выпуск. Проверить первичный запуск, «Новый», редактор и выбор протокола; сохранять явно заданные порты существующих профилей и значения других протоколов.

## macOS — локализация стандартных контролов

- Исправлено по скриншотам: строка search налезала на placeholder, а список языка превращался в два English. Локализация больше не проходит внутрь стандартных AppKit-контролов, English/Русский сохраняются как идентификаторы. Добавлена native-only проверка шести переключений, неизменности поиска и начального SSH/22.

- Тот же механизм применяется к KiTTYgen: English/Русский не переводятся, путь загруженного ключа и публичные данные помечены как raw. Native smoke-test проверяет язык без изменения алгоритма, размера ключа, комментария и данных.
