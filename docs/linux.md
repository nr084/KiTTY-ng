# Linux: сборка и проверка порта

[English](linux.en.md) · [Документация](README.md)

Нативный GTK 3-клиент KiTTY-ng для Linux входит в общий выпуск **0.85-4**. Поставка: AppImage x86_64 и архив AppDir; установка в систему не требуется.

## Архитектура

Клиент использует GTK 3 и существующий терминал PuTTY. SSH, криптография, SFTP/SCP, обработка терминала и генерация ключей остаются общими с Windows и macOS. Для портативных профилей, относительных путей к ключам, сохранённых паролей и передачи настроек утилитам используется общий код существующего macOS-порта.

В пакет входят `kitty-ng`, `kittygen`, `kageant`, `klink`, `kscp` и `ksftp`. Главное окно позволяет искать сеансы, открывать вложенные папки, создавать, изменять, удалять и дублировать профили. Новый SSH-профиль получает порт **22**. Русский и английский интерфейсы переключаются без изменения пользовательских данных.

## Переносимый формат

Основной формат — **AppImage x86_64**. Дополнительный архив `tar.zst` содержит AppDir и позволяет запускать приложение после распаковки, в том числе на системах без FUSE. Разработка и нативные проверки выполняются на Ubuntu 26.04; библиотеки для сборки взяты из Ubuntu 22.04. Совместимость с другими дистрибутивами пока не заявляется.

Общую папку с Windows/macOS-профилями можно выбрать в главном окне или передать явно:

```sh
chmod +x kitty-ng-0.85-4-x86_64.AppImage
./kitty-ng-0.85-4-x86_64.AppImage --portable-dir '/путь/к/общей папке'
```

Без явного выбора приложение использует папку рядом с AppImage. Для распакованного AppDir — папку рядом с AppDir. `Sessions`, `kitty.ini`, `values.ini`, `SshHostKeys` и относительные пути внутри общей папки сохраняют исходный формат KiTTY. Локальный файл случайного состояния Linux называется `kitty-ng-linux.rnd`.

Запуск встроенной утилиты:

```sh
./kitty-ng-0.85-4-x86_64.AppImage --keygen
./kitty-ng-0.85-4-x86_64.AppImage --agent
./kitty-ng-0.85-4-x86_64.AppImage --tool klink -V
./kitty-ng-0.85-4-x86_64.AppImage --appimage-extract-and-run
```

## Сборка на Windows

Компиляция и упаковка выполняются **локально на Windows**. Виртуальная машина используется для получения системных заголовков/библиотек и для проверки готовых файлов; сценарии ниже не запускают на ней компилятор.

Инструменты: Clang/LLD 23.1.3, CMake, Ninja и Perl из локальной установленной инструментальной цепочки. Целевая база в `_tools/linux/sysroot` содержит заголовки и библиотеки Linux; `_tools/linux/target.json` — параметры GTK и перечень версий пакетов. Эти файлы, ключ SSH и скачанные инструменты не входят в Git.

Для повторного получения целевых библиотек из подготовленной базы: `python tools/linux-sysroot.py --host <адрес> --remote-root /opt/kitty-ng/baseline`. Инструмент использует закреплённый ключ сервера и SSH-ключ из `_tools/linux/ssh`, проверяет SHA-256 архива и не запускает удалённую компиляцию.

```powershell
python tools/local-build.py --platform linux
python tools/linux-package-windows.py
```

Первый сценарий создаёт ELF-файлы в `build/linux-windows`; второй собирает AppImage и архив AppDir в `dist/linux`. Упаковка использует Windows-версию SquashFS Tools NG и официальный runtime AppImage. Права Linux записываются в архив явно, независимо от прав файлов Windows. Отчёты: `build/linux-windows/linux-cross-build.json` и `dist/linux/linux-package.json`.

## Проверки

Собранные на Windows файлы проверяются нативно в Ubuntu, а не через эмуляцию ELF на Windows:

- поиск и навигация по папкам, создание и дублирование профилей, порт 22 и относительный путь к ключу;
- сохранность исходного профиля и неизвестных полей старого KiTTY;
- реальное SSH-подключение к OpenSSH и перенос папки с профилями;
- передача файлов через SFTP с пробелами и кириллицей в имени;
- загрузка, перечисление и удаление ключей агента, подключение с его помощью;
- генерация Ed25519 в KiTTYgen и переключение RU/EN без потери ключа и комментария;
- запуск GUI из AppImage, включая проверку от непривилегированного пользователя.

Также проверены реальные Shift+стрелки и F2 в MC, перетаскивание URI без запроса каталога назначения, скачивание через GUI и автоматическое переподключение после обрыва установленного SSH-сеанса. Внешнее изменение профиля во время редактирования блокирует его перезапись.

Проверенная среда — Ubuntu 26.04, Xfce/X11, включая запуск от обычного пользователя. Wayland, другие дистрибутивы и ARM64 пока не проверены. Специфичные для Windows интеграции с оболочкой не входят в Linux-пакет. Подробная область порта: [матрица Linux](linux-migration.json).

Функциональные клавиши новых профилей используют Xterm 216+, соответствующий `TERM=xterm`. Явно сохранённый режим клавиатуры сохраняется; для старого профиля с неработающими F1–F4 выберите Xterm 216+ в настройках клавиатуры. Закрытие терминала отменяет его активные передачи файлов.

## Сочетания клавиш и действия

В настройках окна включите пользовательские сочетания. Секция `[Shortcuts]` в `kitty.ini` совместима с KiTTY: Ctrl+F2 отправляет команду, Ctrl+F3 открывает отправку файлов, Ctrl+F4 — получение, Ctrl+F9 блокирует или разблокирует ввод. Поле `list` задаёт собственные текстовые сочетания. Ctrl+щелчок по HTTP/HTTPS открывает системный браузер; файлы и команды через эту функцию не запускаются. Kageant позволяет удалить отдельный ключ по отпечатку или комментарию.

При отсутствии FUSE используйте `--appimage-extract-and-run` или распакованный AppDir; [руководство AppImage](https://docs.appimage.org/user-guide/troubleshooting/fuse.html).
