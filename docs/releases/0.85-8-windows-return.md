# Передача macOS 0.85-8 Windows-чату

Mac-подготовка выполнена в общей папке KiTTY-NG, исходная база — `e82ef7c4dc6d01689682b528885359305787848f`. Версию не повышать. Итоговый точный коммит, SHA-256 и путь к DMG записаны в `dist/macos-native/macos-0.85-8-delivery.json`; коммит отправлен в origin/main.

## Что изменено после исходной базы

- Mac: runtime-кэш и fallback сохранённого пароля теперь делят одну автоматическую попытку. После одного отказа показывается обычный запрос. Воспроизведение до исправления и серверные счётчики сохранены без значений секретов.
- Добавлены Mac-native regression tests хранения кэша, отказа повторной попытки, OTP/смены identity, отсутствия runtime-поля в записанном профиле и отрисовки серого/красного крестика.
- Новый изолированный fixture `test/macos_native_duplicate_auth.py` проверяет GUI с паролем, защищённым ключом, агентом и OTP. Обновлены снимки RU/EN и Mac-документация.

## Согласование общего выпуска

1. Прочитать AGENTS.md. Сверить чистую рабочую копию с итоговым Mac-коммитом, сохранив чужие изменения. Mac ничего не публиковал и не менял теги.
2. Перед финальной Windows/Linux-пересборкой проверить аналогичный fallback после `kr_auth_reuse` в `windows/window.c` и `unix/window.c`: при успешной выдаче кэшированного SSH-пароля флаги `kr_saved_password_tried` / `saved_password_used` в исходной базе не выставляются. Mac воспроизводит из-за этого две автоматические отправки. На Windows/Linux требуется отдельная нативная проверка случая, когда Conf_password заполнен, сервер сменил пароль, а дубликат использует runtime-кэш; результат Mac не считать их проверкой.
3. Если нужны дополнительные изменения исходников, согласовать новый коммит с Mac и передать его для штатной переупаковки. Не подменять provenance вручную. Номер 0.85-8 сохраняется.
4. Пересобрать Windows x64/x86/ARM64 и Linux из окончательно согласованного коммита штатными tools/local-build.py и tools/linux-package-windows.py, с последним официальным stable и сохранением незатронутых успешных проверок. Mac на Windows не собирать. Сохранить отчёты и нативную Linux-проверку именно поставляемых бинарников.
5. Только после сообщения пользователя о готовности Mac и совпадения происхождения всех шести пакетов Windows-чат выполняет:

```powershell
python tools/release-build.py --assemble-only --macos-dir dist/macos-native
python tools/publish-release.py
```

Публикация только из Windows-чата, без --pending-macos. Сохранить предыдущие релизы и независимый kitty-ng-fs. После публикации проверить все SHA-256 и latest. Mac-артефакты: `kitty-ng-0.85-8-macos-universal.dmg`, `macos-build.json`, `macos-dmg.json`, `gui-acceptance.json`, `runtime-arm64.json`, `runtime-x86_64.json`, `certificates.json`, `proxies-*.json`, `auth-*.json` в dist/macos-native.

## Результат проверки Windows/Linux после Mac-передачи

На Windows и нативной Ubuntu воспроизведены две автоматические отправки старого пароля при заполненном `CONF_password` и смене пароля на сервере. Исправление выставляет флаг использованной автоматической попытки при выдаче runtime-пароля и после отказа пропускает также обработчик командной строки, который может содержать копию сохранённого пароля.

Новый `test/duplicate_password_retry.py` проверяет настоящий GUI каждой платформы: вход из сохранённого профиля, смена пароля сервером, единственный автоматический отказ дубликата, ручной ввод нового пароля и успешный следующий дубликат с обновлённым runtime-кэшем. Нативные проверки Windows и Linux прошли; исходные и итоговые серверные счётчики сохранены в `dist/auth-retry-before-*.json` и `dist/auth-retry-after-*.json` без секретов. Тест включён в штатную Windows-сборку x64/x86 и Linux acceptance поставляемых бинарников.

Это изменение требует нового общего коммита и штатной Mac-переупаковки из него. Принятый DMG из `1365d9a3dfd4d920a380ebe59a49452ff40fd008` нельзя выдавать за сборку нового коммита. Версия остаётся 0.85-8; до готовности соответствующего Mac-пакета публикация не выполняется.
