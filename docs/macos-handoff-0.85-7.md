# Промпт для Mac-чата: KiTTY-ng 0.85-7

Продолжи подготовку **0.85-7** в общей синхронизируемой папке `KiTTY-NG`. Версию повторно не повышай. Windows x64/x86/ARM64 и Linux x86_64 собираются на Windows; здесь их не пересобирай и не заменяй. Их проверенные пакеты и отчёты находятся в `dist`, Linux — в `dist/linux`.

1. Прочитай `AGENTS.md`. Проверь чистоту рабочей копии и исходный коммит в `dist/local-build.json` / `dist/release-build.json`: сборка Mac должна соответствовать согласованным исходникам. Не откатывай чужие изменения. Новый выпуск на GitHub может пока быть черновиком `v0.85-7`, ожидающим DMG.
2. На настоящем Mac проверь у официального поставщика последний стабильный компилятор. При обновлении компилятора сначала пересобери пакеты и только затем тестируй новые бинарные файлы. Сохрани точную версию и сведения об инструментах.
3. Нативно собери Universal 2 (arm64 + x86_64) через `python3 tools/local-build.py --platform macos`. Вкладки Windows/Linux уже реализованы в этом выпуске; **Mac-вкладки сейчас не заявляй реализованными**. Их нативная реализация отложена до отдельного этапа. Не переноси Win32/GTK-код в AppKit автоматически.
4. Проверь GUI, портативный режим, общие Windows-профили, быстрое подключение без записи профиля, Cmd+C/V/X/A, RU/EN, SSH/SCP/SFTP, утилиты и обе архитектуры (x86_64 через Rosetta). Убедись, что приложение и каждый помощник Universal 2; проверь подпись и смонтированный DMG. Готовый файл — `kitty-ng-0.85-7-macos-universal.dmg`.
5. Старые Mac-скриншоты разрешено сохранить, если интерфейс не изменился. Снимки Windows/Linux уже обновлены. Не включай личные пути, адреса, ключи или пароли в документацию.
6. После проверенного Mac-пакета собери общий манифест `python3 tools/release-build.py --assemble-only --macos-dir dist/macos-native` (путь уточни по фактическому выводу сборки). Убедись, что проверки покрывают именно публикуемые бинарные файлы; не подменяй сведения о коммите и прохождении проверок.
7. Обнови статус и ссылки 0.85-7 в RU/EN README и заметках выпуска, затем подготовь согласованные артефакты и манифест. Если документационный коммит меняет проверяемый commit, соблюди процедуру согласованной сборки вместо ручной подмены provenance.
8. Опубликуй подготовленный черновик через `python3 tools/publish-release.py` **без `--pending-macos`** только после полной проверки шести пакетов. Сохрани старые релизы и независимый выпуск плагина kitty-ng-fs. После публикации проверь SHA-256 всех вложений и статус latest основного клиента.
9. Удали только временные загрузки и промежуточные каталоги этого выпуска. Сохрани текущие пакеты, отчёты, исходники, установленные компиляторы и SDK.

Подчеркни в релизе портативный режим macOS и совместимость с Windows-профилями. Не объявляй полный синхронный выпуск завершённым до проверки Mac DMG.
