# Правила разработки kitty-ng

- Основная документация GitHub и заметки к релизам — на русском языке. Сохранять отдельный английский `README.en.md`, взаимные ссылки между README и благодарности авторам PuTTY и KiTTY в обеих версиях.
- В пользовательский changelog включать новые функции, исправления ошибок, изменения совместимости, безопасности и базовой версии PuTTY. Незначительные косметические изменения, например правки копирайта, не включать. Это не ограничивает обычную фиксацию изменений в Git.
- Использовать последнюю стабильную версию компилятора и сохранять точные сведения об инструментах сборки.
- Компилятор LLVM-MinGW устанавливать локально в `_tools/llvm-mingw/<выпуск>/toolchain` и сохранять между сборками. Перед обычной сборкой проверять последний стабильный выпуск; временные загрузки и промежуточные файлы удалять, установленный компилятор не считать временным файлом.
- Собирать и проверять выпуски локально через `python tools/local-build.py`; GitHub Actions для сборки не использовать.
- Версия выпуска имеет вид `<версия базового PuTTY>-<редакция KiTTY-NG>`, начиная с `0.85-1`, далее `0.85-2` и т. д. Базовую часть не менять независимо от PuTTY. Редакция — положительное число; в ресурсах Windows хранить `0,85,1,0` для выпуска `0.85-1`. Обычные выпуски не помечать тестовыми.
- При публикации новых версий сохранять все предыдущие релизы GitHub и их вложения. Не удалять старые релизы, кроме случая нового прямого указания пользователя удалить конкретный релиз. Это правило заменяет прежнее указание удалять предыдущий релиз после публикации нового.
- При переходе на `0.85-1` по прямой команде пользователя удалить существующие релизы `test` из GitHub после успешной публикации. Это разовая очистка; последующие старые релизы сохранять.
- Вносить запрошенные изменения без автоматического выпуска релиза. Создавать и публиковать релиз, включая черновик GitHub, только после новой отдельной прямой команды пользователя на выпуск. Прежние указания публиковать релизы не считать разрешением на следующие выпуски. Без такой команды не повышать стадию версии и не создавать релизные теги; локальная сборка и проверка изменений допускаются.
- Выпуск содержит три ZIP: x64, x86 и ARM64. В имени ZIP указывать версию и архитектуру. Внутри использовать обычные имена EXE без номера версии; все утилиты должны соответствовать архитектуре архива. Встроенные версии EXE сохранять.
- Основной клиент называть `kitty-ng-x86.exe`, `kitty-ng-x64.exe` и `kitty-ng-arm64.exe` соответственно архитектуре; номер версии в имя EXE не добавлять.
- Утилиты внутри ZIP называть `klink-<архитектура>.exe`, `kscp-<архитектура>.exe`, `ksftp-<архитектура>.exe`, `kittygen-<архитектура>.exe`, `kageant-<архитектура>.exe`, где архитектура — `x86`, `x64` или `arm64`.
- При автоматическом запуске клиента и сопутствующих утилит использовать EXE своей архитектуры из каталога вызывающего приложения; проверять архитектуру PE, не подменять отсутствующий файл программой другой архитектуры или найденной через PATH.
- Сохранять совместимость с портативным форматом KiTTY и ранее созданными настройками. Идентификаторы формата хранения не менять ради косметического переименования.
- Ветка реестра проекта — `HKCU\Software\KiTTY-NG`, маркер портативного режима — `kitty-ng.portable`, переменная каталога — `KITTY_NG_PORTABLE_DIR`. Использовать только актуальное имя проекта; это явное правило именования не меняет формат файлов оригинального KiTTY.
- Не добавлять чтение, импорт или автоматическую миграцию настроек прежнего названия проекта: его ветки реестра, портативного маркера и переменной окружения не поддерживать. Совместимость с портативным форматом оригинального KiTTY сохранять.
- Удалять временные загрузки, зависимости и промежуточные каталоги после завершения работы. Готовые архивы сохранять в `dist`.
- Не повторять уже успешно пройденные тесты, если проверяемая ими логика не изменилась. Запускать проверки изменённой логики, новых тестов и воспроизведения новых ошибок; результаты успешных незатронутых проверок сохранять и использовать повторно.

- При отсутствии сохранённого выбора использовать язык интерфейса Windows: русский для LANG_RUSSIAN, английский для остальных. Сохранённый выбор и явный `--language en|ru` имеют приоритет. KiTTYgen переключает язык отдельным меню «Язык» с сохранением настройки и открытого ключа.
