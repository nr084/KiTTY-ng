# KiTTY-ng FS 1.1.0 — встроенный SSH/SFTP

Крупное функциональное обновление плагина Total Commander: **SSH/SFTP теперь работают внутри WFX, без Klink и Plink**. Версия повышена с 1.0.3 до 1.1.0; цикл выпусков плагина независим от KiTTY-ng.

- Использовано существующее ядро PuTTY/KiTTY-ng, статически встроенное в DLL x86/x64.
- Пароль, парольная фраза PPK и keyboard-interactive запрашиваются через Total Commander.
- Новый или изменённый ключ сервера требует подтверждения с отпечатком; отказ не изменяет доверенные ключи.
- Сохранены портативные профили, относительные пути ключей, группы и отображение точек в именах сеансов.
- Для файловых операций EXE клиента не нужен. Необязательная команда `terminal` по-прежнему открывает установленный KiTTY-ng.
- Внешние команды прокси отключены. Пользовательский `kittyngfs.ini` совместим; не заменяйте его при обновлении.

## Установка

Откройте **kitty-ng-fs-1.1.0-x86-x64.zip** в Total Commander, подтвердите установку и перезапустите TC. Выберите папку с портативными профилями KiTTY-ng. Исходники поставляются отдельно в **kitty-ng-fs-1.1.0-source.zip**; контрольные суммы — **SHA256SUMS.txt**.

## Проверка и ограничения

Локальная сборка Windows x86/x64: stable LLVM-MinGW 20261020 / Clang 23.1.4. Проверены реальные WFX-вызовы, файловые операции через локальный SSH/SFTP-сервер, авторизация, ключи сервера, PPK, отмена и тайм-ауты. Подробный отчёт — [PUBLICATION.md](https://github.com/nr084/KiTTY-ng/blob/kitty-ng-fs-v1.1.0/kitty-ng-fs/PUBLICATION.md).

Ручной прогон интерфейса TC и работа с настоящим Kageant в этой проверке не подтверждены. Нет resume, фоновой очереди и прямого копирования между серверами; после простоя может понадобиться повтор подключения. Встроенные сетевые прокси доступны, но все их варианты не проверены.

Основной KiTTY-ng 0.85-6 и предыдущие релизы не изменены.
