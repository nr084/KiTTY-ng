# Правила kitty-ng-fs

- Плагин Total Commander развивается в каталоге `kitty-ng-fs`, пользовательское название — KiTTY-ng FS.
- Цикл выпусков независим от KiTTY-ng. Версию клиента и его релизы не менять при выпуске плагина.
- Текущий выпуск плагина — 1.1.1. При изменении отображаемых имён сохранять исходную идентичность сеанса для встроенного SSH-ядра, различимость имён и совместимые старые пути.
- Собирать локально на Windows последним стабильным LLVM-MinGW; проверять официальный выпуск и SHA-256 загрузки, фиксировать версию компилятора.
- Публиковать отдельно установочный ZIP x86/x64 (без исходников) и полный архив исходников (без готовых WFX и промежуточных файлов).
- В Git хранить исходники, оригинальные значки, тесты и документацию. Готовые пакеты хранить в `dist/` и GitHub Releases.
- Сохранять совместимость пользовательского `kittyngfs.ini` и формата профилей KiTTY-ng.
- Фиксировать план, изменения, проверки, ограничения и сведения о выпуске в Markdown. Не выдавать старые отчёты или статическую проверку за новый интерактивный тест Total Commander.
- Сохранять MIT и сторонние уведомления; не включать ключи, сеансы, пароли и внешний Klink в пакеты.

- После любого релиза удалять временные загрузки, промежуточные сборки и тестовые каталоги. Сохранять готовые текущие пакеты, отчёты и установленный компилятор; после публикации и проверки нового плагина удалять предыдущие GitHub-релизы плагина вместе с вложениями. На GitHub оставлять только последний выпуск плагина и последний выпуск основного клиента; последний клиент и его вложения не изменять. Это правило заменяет прежние указания хранить историю релизов.

- Файловое SSH/SFTP-соединение выполнять внутри WFX, без Klink/Plink и командных оболочек. Переиспользовать текущее ядро PuTTY/KiTTY-ng, не менять основной клиент ради плагина.
- Не изменять CWD, переменные окружения, консоль и обработчики процесса Total Commander. Не оставлять исполняющиеся потоки после выгрузки DLL.
- Подтверждение нового/изменённого ключа сервера и ввод пароля/парольной фразы выполнять через RequestProc Total Commander. Без явного согласия ключ не сохранять.
- Нерелизные сборки сохранять отдельно в dist/development; опубликованные пакеты 1.0.3 не подменять. Исходный ZIP должен включать точные исходники встроенного ядра и его лицензии.

- Крупные функциональные обновления плагина повышают minor-версию с обнулением patch: встроенный SSH без Klink — 1.0.3 → 1.1.0. Исправления — patch. Выпускать только по отдельной прямой команде пользователя.
