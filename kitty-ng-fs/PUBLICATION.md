# Проверка выпуска kitty-ng-fs 1.0.2

Дата: 27 октября 2026 года. Сборка и запуск тестов — локально на Windows, без GitHub Actions. Версия KiTTY-ng остаётся 0.85-6; релиз плагина независимый.

## Компилятор

- Официальный последний стабильный LLVM-MinGW: [20261020](https://github.com/mstorsjo/llvm-mingw/releases/tag/20261020). Проверено через GitHub API `releases/latest`, `draft=false`, `prerelease=false`.
- Clang 23.1.4, UCRT, `llvm-mingw-20261020-ucrt-x86_64.zip`.
- SHA-256 дистрибутива: `fd5462b7f5d93b2ff981fcd3f9c7e427e47f3203c64ea91c27bcc444eebd74cd`, совпал с официальным digest GitHub.
- Сборка C11/O2, `-Wall -Wextra -Wpedantic -Werror`, ASLR/NX, без timestamp линкера.

Два пропуска в тесте профилей: создание файловых и каталоговых Windows symlink недоступно окружению. x86 исполнялся как 32-битный процесс на Windows, x64 — как 64-битный. Проверка ресурсов читает обе DLL как данные; отдельные WFX-тесты действительно загружают и вызывают каждую архитектуру.

Тест 10 000 смешанных соседних элементов / 30 000 поисков на том же компьютере: исходный алгоритм x64 — **1219 мс**, новый — **менее шага GetTickCount64** (результат 0 мс); x86 — 15 мс. Нулевой отсчёт не означает нулевую длительность. Это сравнение локального поиска, не скорости SFTP; результаты зависят от компьютера.

## Ограничения

- Интерактивная установка, диалоги и панели в настоящем Total Commander в этом прогоне не проверялись.
- SSH к ранее разрешённой Ubuntu VM недоступен (тайм-аут). Полный новый сетевой прогон WFX → Klink → OpenSSH для 1.0.2 не заявляется.
- Исторические сетевые проверки 1.0.1 под Wine сохранены отдельно в VALIDATION.md; они не подменяют проверку 1.0.2.
- ASan/UBSan и MSVC для этого выпуска не запускались.

## Повторение

Из корня `kitty-ng-fs`:

```powershell
python build-local.py --toolchain C:\tools\llvm-mingw-20261020
python package.py
```

Локальный подробный журнал: `dist/build-validation.json`. Архивы: `kitty-ng-fs-1.0.2-x86-x64.zip` и `kitty-ng-fs-1.0.2-source.zip`; содержимое разделено, каждый ZIP проверяется упаковщиком. Контрольные суммы публикуются в `SHA256SUMS.txt`. Команда повторения и состав тестов также описаны в tests/README.md.

## Статический анализ и итоговые DLL

Clang Static Analyzer проверил шесть C-модулей. Исправлено удержание указателя на стековый путь после ANSI WFX-вызова; затем повторно собраны обе DLL, пройдены 178 WFX-проверок на каждой архитектуре и 144 проверки ресурсов. Повторный анализ `plugin.c` больше не сообщает StackAddressEscape. Осталось одно проверенное ложноположительное предупреждение `unix.Malloc` на предположении, что успешный calloc возвращает HANDLE -1; обоснование в REVIEW.md.
