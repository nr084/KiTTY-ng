# Встроенный SSH: выпуск 1.1.0

Запрос от 27 октября 2026: перенести файловые соединения внутрь плагина, убрать Klink. По отдельной команде пользователя это крупное функциональное обновление выпускается как 1.1.0. Версия основного клиента 0.85-6 не меняется.

## Реализация

- SSH-2, криптография, чтение профилей, PPK, проверка серверных ключей — статически связанное существующее ядро PuTTY/KiTTY-ng. Собственная реализация SFTP v3 продолжает работать поверх нового канала.
- Файловые операции не запускают Klink/Plink, shell или внешний SFTP-клиент. Для них достаточно WFX, портативных профилей и используемых ключей.
- Пароль, парольная фраза и keyboard-interactive передаются через RequestProc Total Commander. Ввод секретов маскируется; ввод не сохраняется в INI. Сохранённые пароли расшифровывает существующий код KiTTY-ng.
- Незнакомый/изменённый host key требует явного подтверждения с отпечатком. При отказе файл доверия не создаётся и старый ключ не заменяется. При согласии используется общий SshHostKeys.
- Профили не изменяются; исходное имя сеанса, нестандартный порт, относительные пути PPK и портативный корень сохраняются. CWD и окружение Total Commander не меняются.
- Сетевой цикл вызывается из сериализованных операций WFX. Нет фонового потока SSH. Адаптер Pageant использует проверяемый по владельцу named pipe с отменяемым I/O либо ограниченный по времени WM_COPYDATA.
- Отключены agent/X11/port forwarding, PTY, произвольная удалённая команда и SSH sharing. Внешние proxy commands не запускаются; встроенные сетевые прокси доступны.
- Команда `terminal` остаётся необязательной ссылкой на установленный графический KiTTY-ng. Это единственная клиентская утилита в пользовательском потоке; передача файлов от неё не зависит.

## Сборка и проверка

```text
python build-local.py --toolchain <LLVM-MinGW> --tests icons
python tests/test_embedded.py --dll dist/development/kitty-ng-fs.wfx --harness build/x86/test_wfx.exe --auth-harness build/x86/test_auth.exe --report dist/development/ssh-validation-x86.json
python tests/test_embedded.py --dll dist/development/kitty-ng-fs.wfx64 --harness build/x64/test_wfx.exe --auth-harness build/x64/test_auth.exe --report dist/development/ssh-validation-x64.json
```

Для сетевых тестов нужен Paramiko в Python. Сервер слушает только loopback, файловая система синтетическая, приватные тестовые ключи создаются временно. EXE клиентов в тестовой папке отсутствуют. Тесты не используют личные подключения.

Инструменты: LLVM-MinGW 20261020, Clang 23.1.4, UCRT; CMake/Ninja. DLL проверяются нативно на Windows через WFX API, включая выгрузку с активным соединением. Интерактивное окно Total Commander и внешний Kageant в этом прогоне не проверены; это не заменяется тестами ABI. Последовательные запросы SFTP, отсутствие resume/фоновой очереди/межсерверного копирования сохранены. В простое отдельного keepalive-потока нет; закрытое сервером соединение переподключается при повторе операции.

Результаты записаны отдельно в `dist/development`: build-validation.json, ssh-validation-x86.json, ssh-validation-x64.json. Установочные пакеты и отчёты опубликованного 1.0.3 остаются в `dist` без изменений.

## Исходники и поставка

CMake собирает плагин с существующими библиотеками ядра через отдельный hook; исходные файлы основного клиента не редактируются. Адаптеры DLL находятся только в `src/embedded_*.c`. В самостоятельный исходный ZIP включается точный набор отслеживаемых исходников ядра в `engine/` и манифест; приватные и неотслеживаемые файлы не копируются. Runtime ZIP содержит DLL и документацию, исходники поставляются отдельно. Лицензии PuTTY и KiTTY включены в оба пакета.
