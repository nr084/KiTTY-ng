# KiTTY-ng FS 1.1.1

**Автор: nr084**
**Домашняя страница:** [github.com/nr084/KiTTY-ng](https://github.com/nr084/KiTTY-ng)

Файловый WFX-плагин для **Total Commander x86 и x64**, написанный на **C11**.
Открывает удалённые файлы через **SFTP поверх SSH**, используя сохранённые
сеансы из выбранной **портативной папки KiTTY-ng**. В версии 1.1.0 SSH-ядро встроено в DLL; внешний Klink не нужен. Реализация и проверки: [EMBEDDED-SSH.md](EMBEDDED-SSH.md).

В версии **1.0.3** обычные точки в отображаемых именах SSH-сеансов заменяются средней точкой `·`: `mail.example.ru` → `mail·example·ru`. Имя целиком остаётся в колонке «Имя», исходное имя профиля не меняется. Папки групп и имена удалённых файлов не преобразуются. Подробные результаты: [PUBLICATION.md](PUBLICATION.md).

[Обзор и загрузки](README.md) · [English](README.en.md)

## Точки в именах сеансов

`mail.example.ru` отображается как **mail·example·ru**. Только подпись виртуального SSH-сеанса преобразуется: SSH-ядро загружает исходное имя, профили на диске не меняются, удалённый `file.tar.gz` сохраняет своё имя и расширение.

Буквальная средняя точка в исходном имени отображается как `%C2%B7`, а буквальный `%` экранируется. Поэтому разные исходные имена остаются различимы. Существующие правила суффиксов `[SSH]` при совпадении с папкой сохраняются. Старые вложенные пути и плоские закладки принимаются как совместимые псевдонимы; при неоднозначности приоритет имеет текущее отображаемое имя. После входа возвращается новый канонический путь.

## Что именно подключается

В «Сетевом окружении» Total Commander появляется **KiTTY-ng FS**. Внутри —
группы и сохранённые SSH-сеансы выбранной KiTTY-ng. Вход в группу показывает
её содержимое локально; вход в SSH-подключение открывает файлы сервера.

### Значки и группы

| Элемент | Значок | Действие |
|---|---|---|
| KiTTY-ng FS в сетевом окружении | Два терминала в духе KiTTY-ng | Открыть список групп и подключений |
| Группа | Обычная папка Total Commander | Показать вложенные группы и сеансы без подключения к серверу |
| SSH-подключение | Синий терминал с зелёным prompt и стрелкой входа | Подключиться по SSH/SFTP |
| Настройки | Шестерёнка | Выбрать папку KiTTY-ng и параметры |

Например, вместо `VPN%2FACTIVE VPN` в корне теперь есть папка **VPN**,
а внутри — SSH-подключение **ACTIVE VPN**. Поддерживается до 16 уровней групп.
После входа в сервер его обычные каталоги и файлы используют стандартные
значки Total Commander. Стрелка обозначает тип элемента, а не статус «онлайн».

Группы передаются Total Commander как каталоги, а подключения — как ссылки
с отдельным значком. Поэтому обычная сортировка держит группы впереди,
даже если имя подключения по алфавиту стоит раньше имени группы. Это
действует и в корне, и внутри вложенных групп. Вход в подключение — Enter
или двойной щелчок. Настройки общей сортировки самого TC плагин не изменяет.
Сами ссылки сеансов не предназначены для F3/F4/F5/F8; сначала войдите в
подключение, чтобы работать с удалёнными файлами.

Пиктограммы встроены в обе DLL и имеют кадры 16, 20, 24, 32, 40, 48, 64,
128 и 256 пикселей. SVG-исходники и предпросмотр включены в `assets/` в архиве исходников.

Автор и домашняя страница указаны в окне настроек, справке `help` и свойствах
DLL. Кнопка «Домашняя страница» в настройках открывает страницу KiTTY-ng
в браузере. То же действие доступно командой `homepage` в строке TC.

Если в одной группе совпадают имя папки и имя подключения, папка сохраняет
своё имя, а подключение получает суффикс ` [SSH]`. Если такое имя уже занято,
выбирается свободный вариант ` [SSH 2]` и далее. Это только имя в панели;
SSH-ядро загружает исходное имя сохранённого сеанса.

Плагин создаёт файловое пространство **внутри Total Commander**. Он не
устанавливает WinFsp/SSHFS-Win и не монтирует букву диска для других программ.
SFTP — файловый протокол внутри SSH; именно через него реализован доступ.

## Требования

- Windows 10/11, x86 либо x64; для x64 необходима 64-битная Windows.
- Современный Total Commander с поддержкой Unicode WFX.
- Портативная KiTTY-ng. Интеграция проверена с **v0.85-6** из
  [nr084/KiTTY-ng](https://github.com/nr084/KiTTY-ng/releases/tag/v0.85-6).
- На сервере должен быть включён SFTP subsystem. Unix-shell для файловых
  операций не используется.
- Папка плагина должна разрешать запись `kittyngfs.ini`.

Разрядность WFX выбирается по Total Commander: `kitty-ng-fs.wfx` для x86, `kitty-ng-fs.wfx64` для x64. Для файловых операций внешние утилиты не нужны.

Только необязательная команда `terminal` требует `kitty-ng-x86.exe` либо `kitty-ng-x64.exe` в указанной папке. Пользовательские профили, пароли и ключи в пакеты не включаются.

## Установка

1. Откройте ZIP с плагином непосредственно в Total Commander и согласитесь
   на установку WFX. В корне архива находится `pluginst.inf`.
2. Либо распакуйте архив, откройте **Конфигурация → Настройка → Плагины →
   Плагины файловой системы (.WFX) → Настроить → Добавить** и выберите
   `kitty-ng-fs.wfx`. Файл `kitty-ng-fs.wfx64` должен лежать рядом; 64-битный TC
   подхватит его по тому же базовому имени. Названия пунктов зависят от
   версии и перевода Total Commander.
3. Откройте **Сетевое окружение → KiTTY-ng FS**.
4. Откройте элемент **[Настройки KiTTY-ng]**, укажите существующую портативную
   папку KiTTY-ng и сохраните настройки.
5. Начальный каталог: `/` — корень сервера, `.` — домашний каталог
   SSH-пользователя. Это общий параметр для подключений плагина.
6. Откройте нужный сеанс. Список обновляется при перечитывании корня плагина.

Папку можно задать относительным путём от папки плагина либо через
переменную окружения, например `%COMMANDER_PATH%\Tools\KiTTY-ng`.
Кнопка «Обзор» старается сохранить относительный путь на том же диске.
Это позволяет переносить всю папку Total Commander вместе с KiTTY-ng.

Настройки хранятся **рядом с плагином**, отдельно от настроек KiTTY-ng.
Пример — `kittyngfs.example.ini`. Не заменяйте им рабочий INI при обновлении.

### Обновление с 0.1.0 или 1.0

Установите автоустановочный ZIP в прежнюю папку плагина. Завершите текущие
передачи и после обновления полностью перезапустите Total Commander, чтобы
он загрузил новые DLL и перечитал значки. Если установщик сообщает, что DLL
занята, сначала закройте панели плагина и перезапустите TC.

Путь к KiTTY-ng остаётся в существующем `kittyngfs.ini`. В ZIP нет рабочего
INI, а имена `kitty-ng-fs.wfx` и `kitty-ng-fs.wfx64` сохранены.

## Сеансы и аутентификация

Сохранённый профиль загружает встроенное ядро PuTTY/KiTTY-ng. Оно устанавливает SSH-2-соединение и запрашивает подсистему `sftp`; SFTP-операции выполняет код плагина. Пароль не передаётся командной строкой и не записывается в `kittyngfs.ini`.

Поддерживаются сохранённые пароли, приватные PPK-ключи, ключи в Kageant/Pageant, интерактивные пароли, парольные фразы и SSH keyboard-interactive. Диалоги вызывает сам плагин через Total Commander. Новый или изменённый ключ сервера сохраняется в `SshHostKeys` только после явного согласия пользователя. Сверяйте отпечаток с администратором сервера.

Относительные пути к ключам отсчитываются от портативного корня; имя профиля, нестандартный порт и формат хранения сохраняются. Файлы профилей не переписываются. Общий корень, CWD и переменные окружения процесса Total Commander не изменяются.

Для файлового соединения отключены PTY, X11/agent/port forwarding, SSH sharing и произвольная удалённая команда. Поддерживаются встроенные сетевые прокси; запуск внешних команд прокси запрещён.

## Список профилей

- По умолчанию читается `Sessions` внутри выбранного portable root.
- Поддерживаются `[KiTTY] fileextension` из `kitty.ini` и параметры
  `Sessions`, `sessionsuffix` из `putty.conf`, включая относительные пути
  и подстановку переменных окружения.
- Файлы KiTTY-ng имеют формат `Key\value\`; это не обычные INI-файлы.
- Показываются профили с явным `Protocol=ssh` и непустым `HostName`.
- `Default Settings`, другие протоколы, `.tmp` и reparse points пропускаются.
- Группы отображаются как настоящая иерархия: `Работа/Сервер` доступен по
  пути `\Работа\Сервер`. F2 в группе перечитывает локальные профили.
- Старые пути вида `\Работа%2FСервер` принимаются как совместимые закладки,
  если они не конфликтуют с новым деревом. В списке такие псевдонимы не
  дублируются. При неоднозначности приоритет имеет новое дерево.
- Каждая видимая компонента ограничена 255 символами, полный WFX-путь —
  1023. Общая длина группы и имени больше 255 поддерживается.
- Группы предназначены для навигации; изменение структуры профилей следует
  выполнять в самой KiTTY-ng. Невалидные или неоднозначные имена не выбирают
  произвольный сервер: возвращается диагностическое сообщение.
- Поддерживаются обычные Unicode-папки KiTTY-ng и её каноническое
  `%XX`-кодирование файлов сеансов. Нестандартные физические имена папок и
  файлов, которые ядро разрешило бы в другой профиль, пропускаются с
  предупреждением. Плагин сверяет именно тот файл, который загрузит встроенное ядро.

После изменения параметров сеанса выполните `disconnect` и подключитесь
повторно, либо используйте `refresh` для перечитывания всех сеансов и
закрытия старых соединений.

## Операции

| Действие | Поддержка |
|---|---|
| Каталоги, размеры, даты, Unix-права | Да |
| F5: скачать / загрузить | Да |
| F6: перенос между локальной и удалённой стороной | Да, источник удаляется после успешной передачи |
| Переименовать / перенести внутри одного сеанса | Да |
| F7: создать каталог | Да |
| F8: удалить файл или пустой каталог | Да; обход дерева выполняет TC |
| F3/F4 и обычное открытие | TC получает локальную копию; обратная загрузка через стандартный механизм WFX |
| Unix chmod | Через «Файлы → Изменить атрибуты» |
| Изменить время доступа / модификации | Да, в пределах SFTP v3: 1970–2106 |
| Переход по символьной ссылке на каталог | Да, через разрешение цели; ссылка при перечислении остаётся файлом |
| Возобновление частичной передачи | Нет |
| Фоновая очередь WFX | Нет; операции последовательные |
| Прямое копирование сервер → сервер | Нет; используйте промежуточную локальную копию |
| Windows-атрибуты hidden/system/archive и время создания | Не эмулируются |

Плагин держит до 16 соединений; неиспользуемое соединение закрывается при
необходимости. Листинги каталогов независимы: рекурсивные операции TC могут
держать несколько результатов перечисления одновременно. Действует
предел 100 000 записей на один каталог и 10 000 профилей. При превышении
лимита каталог не выдаётся как успешно прочитанный частичный список.

Команды в командной строке TC, когда активна панель плагина:

| Команда | Действие |
|---|---|
| `terminal` | Открыть выбранный сохранённый сеанс в KiTTY-ng |
| `disconnect` | Закрыть SSH-соединение текущего сеанса |
| `refresh` | Закрыть соединения и перечитать профили |
| `settings` | Настройки плагина |
| `homepage` | Открыть домашнюю страницу KiTTY-ng в браузере |
| `help` | Краткая справка |

Произвольные shell-команды не исполняются. `terminal` открывает сохранённый
сеанс, без автоматического перехода в текущий удалённый каталог TC.

## Имена файлов

Обычные Unicode-имена, кириллица, пробелы и знак `%` сохраняются буквально.
Например, `100%20.txt` остаётся именно `100%20.txt`.

Для имён, которые Windows не может представить напрямую (`:`, `\`,
управляющие байты, невалидный UTF-8, имя `CON`, точка/пробел в конце),
используется обратимая метка `~kg~` плюс шестнадцатеричные байты полного
имени. Например, `a:b` показывается как `~kg~613A62`. Реальное имя на
сервере при скачивании или удалении не меняется. Локальная копия получает
имя, выбранное Total Commander, обычно эту отображаемую метку.

Префикс `~kg~` зарезервирован. Неявная загрузка локального файла с таким же
именем запрещена, чтобы не спутать буквальное имя с удалённой меткой.
Для обратной загрузки такой копии сначала дайте локальному файлу обычное
имя, затем явно укажите нужную удалённую метку в диалоге F5. Автоматический
F4 save-back для таких редких имён не поддерживается. Реальное удалённое
имя, начинающееся с `~kg~`, также получает полную обратимую метку.

Имена, не помещающиеся в поля Total Commander после преобразования,
пропускаются с сообщением в журнале. Путь обычной WFX-операции ограничен
интерфейсом TC. Переход в подключение и по символьной ссылке через
FsExecuteFile дополнительно имеет предел 259 символов. Для входа в сеанс
в этот предел входит добавленный завершающий `\`: путь группы и сеанса
без него должен занимать не более 258 единиц UTF-16. Слишком длинный путь
отклоняется с диагностикой без запуска SSH; его имена можно сократить в
KiTTY-ng. Прямое перечисление и файловые операции WFX по-прежнему допускают
пути до 1023 символов. Начальный каталог является логической точкой входа,
а не серверным chroot и не ограничением прав SSH-пользователя.

## Сохранность данных

- Скачивание идёт в случайный временный файл в той же локальной папке.
  Назначение заменяется после завершения передачи и записи данных.
- Загрузка идёт в `.kittyngfs-<случайное имя>.part` рядом с назначением.
  Замена существующего файла выполняется только через объявленное сервером
  расширение `posix-rename@openssh.com`. При отсутствии расширения
  существующий файл остаётся на месте; можно загрузить под новым именем.
- При отмене или обрыве соединения старое назначение сохраняется, если
  замена ещё не выполнена. Удалённый временный `.part` может остаться при
  разрыве SSH; его путь выводится в журнал. Удалить его можно после проверки.
- Новые файлы создаются с правами **0600**. При замене обычного файла
  сохраняются его обычные rwx-биты; setuid/setgid/sticky не переносятся.
  Нужные дополнительные права задайте через chmod в Total Commander.
- Атомарная замена создаёт новый inode: владельца, группу, ACL, xattr,
  SELinux-контекст и связь с другими hard links старого inode плагин не
  воспроизводит. Для файлов, которым требуется сохранение такой метаинформации,
  используйте подходящий административный способ обновления.
- F6 копирует, затем удаляет источник. Это не единая транзакция между
  компьютерами. При ошибке удаления сохраняются обе копии и возвращается
  ошибка. Не изменяйте исходные файлы параллельно с переносом.

Тайм-аут 5–600 секунд ограничивает ожидание сетевого обмена; операция отменяется через callback Total Commander. SSH обрабатывается последовательно во время WFX-операций. В простое отдельного фонового сетевого потока нет: если сервер закрыл неактивное соединение, потребуется повторить операцию для переподключения. Ожидание ответа пользователя в диалоге не считается сетевым тайм-аутом.

## Сборка из исходников

Используйте последний стабильный LLVM-MinGW и `python build-local.py --toolchain <путь>`. Нужны CMake и Ninja; их пути можно передать через `--cmake` и `--ninja`. Новые DLL и отчёт записываются отдельно в `dist/development`. Компилируется статическое ядро из родительского проекта, а для самостоятельного архива исходников — из `engine/`. Основной клиент не изменяется.

Состав исходного ZIP включает точный снимок исходников ядра и лицензий. Runtime ZIP включает WFX и документацию, без исходников, EXE и пользовательских данных. Команды проверок — в `tests/README.md`; результаты разработки — в `EMBEDDED-SSH.md`.

Основные модули:

| Файл | Назначение |
|---|---|
| `plugin.c`, `wfx.h` | Экспорты WFX, операции, интерфейс, конфигурация |
| `profiles.c` | Портативные профили и проверка архитектуры утилит |
| `session_tree.c` | Вложенные группы, однозначные пути, совместимость старых закладок |
| `transport.c`, `embedded_*.c` | Встроенный SSH, профиль, ключи, тайм-аут, отмена, жизненный цикл DLL |
| `sftp.c` | Ограниченный по размеру бинарный SFTP v3, без shell-команд |
| `pathutil.c` | Unicode, файловые имена, длинные пути, время, quoting |

Скачивание использует окно до 32 запросов по 32 КиБ (1 МиБ), чтобы не ждать один round-trip на каждый блок. Загрузка на сервер остаётся последовательной. Процент в WFX целый; переданный объём в МиБ также выводится в журнал TC до достижения первого процента.
