# KiTTY-ng FS · Total Commander

**Русский** | [English](README.en.md) · [KiTTY-ng](https://github.com/nr084/KiTTY-ng)

**SFTP в Total Commander с портативными профилями KiTTY-ng.** SSH и SFTP выполняются внутри WFX x86/x64: Klink, Plink и отдельные криптографические DLL не требуются.

> **1.1.1:** ускорено скачивание больших файлов на соединениях с задержкой; переданный объём в МиБ виден в журнале TC. Встроенный SSH/SFTP не требует Klink. [Реализация и проверки](EMBEDDED-SSH.md).

Плагин выпускается отдельно от клиента. KiTTY-ng/Klink, профили и ключи в комплект не входят. Версия клиента — **0.85-6**, версия плагина — **1.1.1**.

## Точки в именах сеансов

`mail.example.ru` отображается как **mail·example·ru**. Только подпись виртуального SSH-сеанса преобразуется: SSH-ядро загружает исходное имя, профили на диске не меняются, удалённый `file.tar.gz` сохраняет своё имя и расширение.

Буквальная средняя точка в исходном имени отображается как `%C2%B7`, а буквальный `%` экранируется. Поэтому разные исходные имена остаются различимы. Существующие правила суффиксов `[SSH]` при совпадении с папкой сохраняются. Старые вложенные пути и плоские закладки принимаются как совместимые псевдонимы; при неоднозначности приоритет имеет текущее отображаемое имя. После входа возвращается новый канонический путь.

## Возможности

- Вложенные группы и SSH-сеансы в сетевом окружении TC; группы идут перед подключениями при обычной сортировке с папками в начале.
- Просмотр, скачивание, загрузка, переименование, создание и удаление каталогов; Unix-права и время изменения.
- Unicode-имена, отмена операций, временные файлы перед заменой назначения.
- Запуск терминала KiTTY-ng для текущего сеанса командой `terminal`.
- Относительный путь к портативной KiTTY-ng, собственные настройки рядом с плагином.

## Установка

1. Подготовьте папку с сохранёнными SSH-профилями KiTTY-ng. Для версии 1.1.1 достаточно профилей и используемых ключей; EXE клиента для передачи файлов не нужен.
2. Откройте установочный ZIP в Total Commander и подтвердите установку WFX. Для ручной установки выберите `kitty-ng-fs.wfx`; `kitty-ng-fs.wfx64` должен лежать рядом.
3. Откройте **Сетевое окружение → KiTTY-ng FS → [Настройки KiTTY-ng]** и выберите портативную папку клиента.
4. Войдите в нужную группу и сеанс. Начальный каталог `/` означает корень сервера, `.` — домашнюю папку пользователя.

Для версии 1.1.1 требуются Windows 10/11, Total Commander с Unicode WFX и SFTP на сервере. Впервые увиденный или изменившийся ключ сервера запрашивает подтверждение внутри TC. Пароль и парольная фраза ключа вводятся там же. Настройки сохраняются в **`kittyngfs.ini`**: прежнее имя оставлено для совместимости. При обновлении старого `kittyngfs` выберите прежнюю папку и обновите регистрацию WFX на новое имя, затем перезапустите TC; пользовательский INI не заменяйте.

## Ограничения и проверка

Поддерживаются сохранённый пароль, интерактивные SSH-запросы, PPK и Kageant/Pageant. Нет возобновления передачи, фоновой очереди и прямого копирования между серверами. Внешние команды прокси отключены; доступны встроенные SSH/HTTP/SOCKS-прокси. Плагин не монтирует диск Windows.

## Разработка

Локальная сборка: `python build-local.py --toolchain C:/tools/llvm-mingw-20261020`. Нужны CMake и Ninja. Результат — `dist/development/`, опубликованные пакеты не перезаписываются. SSH-ядро берётся из родительского проекта, а в отдельном архиве исходников — из `engine/`. `build-windows.cmd` вызывает ту же сборку; `build-cross.sh` предназначен для кросс-компиляции без запуска Windows-тестов. Подробности: [встроенный SSH](EMBEDDED-SSH.md), [проверки](tests/README.md).
